# UI Polish Pass Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Nine small frontend fixes: stable Diagnostics header, Follow vehicle in Dispatch settings everywhere, collapsible attribution, sine-wave logo, redesigned ITS feedback control, plus four trial polish items.

**Architecture:** A shared `WorkspaceHeader` replaces the two header implementations. A small follow registry, scoped by a context inside `WorkspaceShell`, lets every live `MapContainer` expose its camera to the Dispatch settings chip without prop drilling. All other items are local component and CSS changes.

**Tech Stack:** Next.js (App Router), React, Tailwind v4 + `src/app/globals.css`, MapLibre GL, Vitest (`renderToStaticMarkup` + pure helpers), `@playwright/cli` for visual checks.

**Spec:** `docs/superpowers/specs/2026-10-26-ui-polish-design.md`

## Global Constraints

- Frontend only. No schema, OpenAPI or generated-type changes. No new npm dependencies.
- Reuse existing tokens: `--go`, `--caution`, `--emergency`, `--muted-foreground`, `--ease-out`, `--dur-press` (120ms), `--dur-hover` (150ms), `--dur-enter` (200ms), `--track`, `--thumb`, `--thumb-shadow`; classes `surface-glass`, `pressable`, `workspace-button`, `hud-segmented`, `hud-segment`, `tone-*`, `hud-value`.
- Hover-only styling goes behind `@media (hover: hover) and (pointer: fine)`. Motion respects `prefers-reduced-motion: reduce` (opacity only).
- Tests follow the repo style: `renderToStaticMarkup` markup assertions and pure-function tests. No testing-library.
- Playwright output only under `.tmp/playwright/`; use the `playwright-cli` skill, never `@playwright/mcp`.
- Checks (run in `frontend/`): `npm run lint && npm run typecheck && npm run format:check && npm test && npm run build`.
- Commits: `<category>: <message>`, explicit paths only, end with the `Co-Authored-By` trailer from the session. No push.

## Review Focus

1. **Overlay collisions:** the Dispatch settings chip now appears in operator and Comparison live views where the `.workspace-camera-controls` row and `.comparison-pane-chips` already sit near the top-left. Expect no overlap at 1440×900 and 390×844. Task 8 Step 6 screenshots both.
2. **Follow when the vehicle is idle:** turning Follow on before the first telemetry tick or after arrival must not throw or jump to `[0,0]`. `createMapCamera.display` already guards on `fresh && last`. Task 7 pins "setFollowing(true) with no targets is a no-op".
3. **Comparison follow with one pane unmounted:** unregistering one map must leave the other controllable. Task 7 pins unregister → snapshot recomputes.
4. **Attribution on touch:** a tap must open it and a second tap close it. Hover CSS must not leave it stuck open on phones. Task 5 Step 5 checks a phone viewport.
5. **Disabled ITS cards:** keyboard focus must skip the group when disabled, and the shown value must be Nominal regardless of the stored scenario. Task 6 pins both in markup.

**Interfaces:**
- Produces in `lib/follow-registry.ts`:
  - `type FollowTarget = { following: boolean; resume(): void; showRoute(): void }`
  - `type FollowSnapshot = { available: boolean; following: boolean }`
  - `createFollowRegistry(): { register(id: string, target: FollowTarget): () => void; setFollowing(on: boolean): void; getSnapshot(): FollowSnapshot; subscribe(listener: () => void): () => void }`
  - Semantics:
    - `available` means at least one target is registered.
    - `following` means available and every target is following.
    - `setFollowing(true)` calls `resume()` on each target and `setFollowing(false)` calls `showRoute()`.
    - Re-registering an id replaces the target.
    - The snapshot object is referentially stable until a value changes (needed for `useSyncExternalStore`).
- Produces in `follow-context.tsx`:
  - `FollowProvider({ children })`;
  - `useFollowControl(): FollowSnapshot & { setFollowing(on: boolean): void }`, which returns `{ available: false, following: false, setFollowing: () => {} }` outside a provider;
  - `useFollowTarget(target: FollowTarget | null): void`, which registers with `useId()` and unregisters on null or unmount.
- Consumes: `useMapCamera(...)` returns `{ mode, resume, showRoute, display }` (existing).

- [ ] **Step 1: Failing tests** in `follow-registry.test.ts`:
  - The empty snapshot is `{available:false, following:false}`, and `setFollowing(true)` with no targets does not throw.
  - Two targets, one following: `following` is false. `setFollowing(true)` calls both `resume` spies; `setFollowing(false)` calls both `showRoute` spies.
  - Unregistering the non-following target makes `following` true and notifies subscribers once.
  - `getSnapshot()` returns the same object across calls with no change.
  - Re-registering the same id with `following: true` updates the snapshot.

# Polish and English localization review — 2026-10-30

## Scope and implementation

Reviewed all six documentation tabs in PL and EN: About, Technologies, Data, Architecture,
Details and Development. Also reviewed the homepage, both simulation modes, comparison,
driver, diagnostics, shared controls, status/error messages, accessible labels, metadata,
localization helpers and hardcoded presentation strings. An AST inventory was used to locate
strings outside the dictionaries, including conditional content.

Existing architecture retained: English source keys in `polish.ts`, typed bilingual documentation,
and view-specific copy helpers. No routing, API, state-management, simulation, CSS or dependency changes.
Raw JSON, API identifiers, source attributions, proper names, units, formulas and interpolation slots
remain machine-readable and unchanged. State names in technical tables remain canonical; friendly
status labels are localized. Existing snapshots were updated for deliberate copy changes only.

The mandatory About copy is present verbatim in three separate paragraphs per language. All four
Applications entries are present, including **Efektywniejsze zarządzanie ruchem** and its English
counterpart. An explicit introduction marks these as potential applications, not measured traffic gains.

Terminology: **przejazd bez priorytetu** / **without traffic signal priority** for the Standard mode;
**wybór jednostki** for ranking; **przygotowanie do przejazdu** for clearing;
**powrót do zwykłego programu** for recovery; **krok symulacji** for a tick.
`mock`, `STANDARD_FALLBACK`, ITS enums, configuration names and equations remain technical identifiers.

## Technical decisions

- Corrected the claim that ITS answers can end a run: failed requests fall back at their own
  intersections and the run continues. Server errors and explicit cancellation remain separate.
- Corrected the Polish 15 km/h maximum claim: sizing uses an intended lower speed bound;
  merged/truncated windows can still violate it, as the audit already explains.
- Queue discharge, congestion reduction and gradual recovery remain intended capabilities,
  not simulated or measured results.
- Kept the supplied About wording. The more detailed resource-aware selection policy remains
  documented: the recommended in-area team can arrive up to 60 s later than the fastest.
- No blocking product decision is required. The public distinction between base and team is
  preserved according to context; official data and raw diagnostic payloads are not rewritten.
